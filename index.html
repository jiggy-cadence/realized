Both tables show the actual return over the measured 30-day window, not an annualised projection. Annualising a short window inflates it — a token that fell 92% in a month reads as −988% once multiplied by 12, which is not a number that can happen: an LP cannot lose more than the stake. Where a pool would still print past that floor it is marked * and held at −100%.

This is a track record, not a forecast. We tested predictive pool selection directly: one formation/holdout split showed a +1.64pt edge, then five walk-forward re-runs with the same untuned scorer returned −0.11, +0.04 and +0.26pt against a pre-registered ≥0.5pt bar — all five failed. So we don't sell a tip sheet. We publish which advertised numbers have historically told the truth, and let you decide. Agents: GET /api/rank?trust=historically+honest or the rank_pools MCP tool.

DefiLlama says 40% APR. Should you believe it?

DefiLlama is where most people shop for yield, and it ships an ML prediction on every pool. Nobody publishes whether those predictions were right — so we graded them: 8,092 instances across 459 pools, from 26 archived snapshots of their own live site. The answer has two halves that point opposite ways.

Their raw accuracy is a mirage

The edge over a naive baseline flips sign depending on how much APR movement you allow. A number that changes sign when you move an arbitrary knob is a parameter, not a finding.

toleranceaccuracybaselineedge
strict 0% 53.8% 55.2% -1.4pp
mid 5% 57.7% 53.2% +4.5pp
loose 10% 60.7% 59.2% +1.5pp

But their confidence is honest

Sorted by DefiLlama's own stated confidence, the edge rises monotonically. When they say they're sure, they've earned it. When they aren't, the prediction is worth nothing.

their confidencenaccuracyedge
tier 1 (lowest) 1,987 52.5% -0.3pp
tier 2 2,639 56.7% +3.1pp
tier 3 (highest) 3,466 61.4% +8.3pp

How to use this: trust their top-tier predictions, ignore their bottom-tier ones — and in every tier remember what's being predicted is fee-only APY, which has no impermanent-loss term. That's the number this whole site exists to correct. Grader canary: oracle 100%, inverted 0%, coinflip 50% — it provably tells a perfect predictor from an inverted one.

Method, limits, and everything we got wrong on the way here

What is being computed

Realized return = fee income + impermanent loss (IL is always ≤ 0). Advertised APR is the most recent day's fees annualized on current TVL — the standard DEX-UI formula. Both come from The Graph's historical poolDayData: per-day fee totals in USD are derived aggregates produced by the indexer. You could rebuild fee accrual from RPC — feeGrowthGlobal0X128 is public pool state at any historical block, and we checked that against a live archive node rather than assuming — but turning a Q128 token-unit accumulator into per-day USD needs an archive node, a block lookup per day boundary, and a historical price for both tokens at each one, repeated per pool. The claim is practicality, not impossibility.

IL is recomputed in your browser from the pool's price ratio and the range you pick, using the same closed form as lib/concentrated.js, which the test suite pins against the standard v2 formula at four range widths. Nothing is precomputed per range.

Why the range matters

Uniswap v3 LPs concentrate into a price band. Inside a band IL is amplified; once price leaves the band you're fully converted into the losing asset and the loss is no longer impermanent. Full-range is the most generous possible case for the pool, which is why it's the last option, not the default.

The fee term is held constant across ranges, which is deliberately unfair to us: concentrating earns more fees too, so some IL is earned back. We can't measure per-position fees from pool-level data, so we didn't model the uplift. The direction is what survives; treat magnitudes as bounded by that.

How well does it hold up

110 independent (non-overlapping) 30-day windows across 4 chains, plus the same instrument run unchanged on Aerodrome Slipstream — a different team, codebase and incentive model — showing the same defect, same shape. Full tables: the measurement report.

Things that are true and inconvenient

  • An earlier headline of corr = 0.06 is retracted. It existed in no committed code and does not reproduce. Recomputed honestly it spans Pearson 0.08–0.16 / Spearman 0.30–0.33 depending on gate, trimming and estimator — that spread is the finding.
  • We shipped the Uniswap v2 formula on a v3 venue before 2026-09-07, silently reporting the best case for every pool. Fixed; the old number survives as the "full range" option so the change stays auditable.
  • Venues we couldn't validate are excluded, not called clean. A venue only appears if its stable/stable pairs prove ~0 IL in the same run. SushiSwap v3, PancakeSwap v3, QuickSwap v3 and Camelot v3 are reported as unmeasurable, not as clean.
  • Survivorship bias, and it points against us. Pools are ranked by current volume, so pools that died are absent — making the past look better than it was.
  • "LPs lose to HODL" is not our discovery (Topaze Blue / Bancor, 2021). Our contribution is calibrating the advertised metric against it, live, per pool.
