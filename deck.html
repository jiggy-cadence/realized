The cause

Advertised APR has no price term. It cannot show a loss.

Every DEX computes advertised APR as fees ÷ liquidity, annualized. Fees are always ≥ 0, so the number is positive by construction — it is structurally incapable of reporting that you lost money.

What's missing is impermanent loss: the cost of the pool rebalancing you out of the asset that went up. Add the price term back and you get the number that was always the actual answer.

realized return = fees + impermanent loss(price ratio, range width)

Not our discovery that LPs can lose to HODL — Topaze Blue / Bancor established that in 2021. Our contribution is calibrating the advertised metric itself, pool by pool, against what happened.

Same pools, same window, only the assumed range changes. The direction never flips: the tighter and more realistic your position, the more the advertised number lies to you. Full-range is the most generous possible case for the pool, and the defect is still there. Measured across 4 chains — mainnet, arbitrum, polygon, base.

Fees are held constant across ranges, which is deliberately unfair to us: concentrating earns more fees too. We can't measure per-position fees from pool-level data, so we report the direction and treat magnitudes as bounded by that caveat.

The Graph — the dataset

Per-day feesUSD are indexer-derived aggregates. You could reconstruct fee accrual from RPC — feeGrowthGlobal0X128 is public pool state at any historical block, and we verified that against a live archive node rather than assuming. What is not tractable is the join: that accumulator is Q128 in token units, so per-day USD needs an archive node, a block lookup per day boundary, and a historical price for both tokens at each one — then repeated for every pool. At 376 pools across 4 chains that is thousands of archive calls per rebuild. The Graph publishes that join already computed and consistent. The claim is practicality, not impossibility — an earlier draft of this slide said “impossible,” which was too strong, and correcting it is the same discipline the rest of this deck is about.

What we refused to ship

We tried to predict which pools will pay. It failed. So we killed it.

A single formation/holdout split said we had a pool-picking edge of +1.64pp (12 picks from 61 pools, verdict "SIGNAL"). That would have been the flashiest thing in this submission. So we tried to break it: same scoring function, deliberately not retuned, walked forward across real time.

Swipe the table sideways for every column →

Pre-registered bar, set before the runs: median edge ≥ 0.5pp, ≥ 60% positive windows, p ≤ 0.05. Every run clears the positive-window gate and still fails — the median edge never reaches the bar and the p-value never gets close. A cost model of 0.1% round-trip is charged on every pick.

The bar tests the median window edge, so the median is what's bolded; the mean is shown beside it because they disagree, and picking whichever one looks better after the fact is the exact error this table exists to prevent. Caveat we can't remove: adjacent windows share market regime, so they are not fully independent.

So REALIZED ships a track record — what already happened, measured — and never a forecast. Five independent walk-forward runs, five failures, zero retuning. The interesting result was the one we threw away.
